[Expo Router](https://docs.expo.dev/router/introduction/) is a popular routing library from Expo that is built on top of React Navigation. When using Unistyles with Expo Router, it's necessary to configure it properly.

### Modify main entry

Expo Router resolves routes differently than expected. Also, Unistyles 3.0 is parsing your `StyleSheets` as soon as you import file containing it.
This combination may cause some issues. To prevent that you need to modify your main entry file:

```diff lang="json" title="package.json"
{
-   "main": "expo-router/entry"
+   "main": "index.ts"
}
```

Then, create `index.ts` (or `index.js`) file with following content:

```js title="index.ts"
import 'expo-router/entry'
import './unistyles' // <-- file that initializes Unistyles
```

<Aside>
The `unistyles.ts` file is where Unistyles is configured. For more details, refer to the [configuration guide](/v3/start/configuration).
</Aside>

With this setup, we will ensure that Unistyles is initialized before any other component.

<Aside>
Expo Router is built on top of React Navigation, so screens can be frozen when they are not focused (`freezeOnBlur`). Unistyles supports frozen screens, learn more [here](/v3/guides/why-my-view-doesnt-update#problem-5-frozen-or-hidden-screens).
</Aside>

### Expo Router Web - Static rendering

:::caution
This is the default option since Expo SDK 52.
:::

You can check if you are using static rendering in `app.json`:

```json title="app.json"
{
  "expo": {
    "web": {
      "bundler": "metro",
      "output": "static"
    }
  }
}
```

For Expo static rendering, every page will be resolved with the root HTML file. Unfortunately, this file is hidden, and you need to create it manually.
Please follow the [Expo guide](https://docs.expo.dev/router/reference/static-rendering/#root-html) and add a `+html.tsx` file.

In this file, initialize Unistyles by importing the config file:

```diff lang="tsx" title="+html.tsx"
import React from 'react'
import { ScrollViewStyleReset } from 'expo-router/html'
import { type PropsWithChildren } from 'react'
+ import '../unistyles' // <-- file that initializes Unistyles

export default function Root({ children }: PropsWithChildren) {
    ...
}
```

This ensures that Unistyles is initialized whenever Expo Router renders the next static page.

### Expo Router Web - Server rendering

With server rendering (`"output": "server"`, Expo SDK 58 and later), Expo renders every page on request with the same `+html.tsx` file.
The server doesn't run your main entry, so import the config file in `+html.tsx`, and render the page's styles with `useServerUnistyles`:

```tsx title="+html.tsx"
import '../unistyles' // <-- file that initializes Unistyles
import { useServerDocumentContext } from 'expo-router/html'
import { type PropsWithChildren } from 'react'
import { useServerUnistyles } from 'react-native-unistyles/server'

// Rendered after the page, so it collects the styles the page rendered
const UnistylesStyles = () => <>{useServerUnistyles({ includeRNWStyles: false })}</>

export default function Root({ children }: PropsWithChildren) {
    const { htmlAttributes, bodyAttributes, headNodes, bodyNodes } = useServerDocumentContext()

    return (
        <html {...htmlAttributes}>
            <head>{headNodes}</head>
            <body {...bodyAttributes}>
                {children}
                <UnistylesStyles />
                {bodyNodes}
            </body>
        </html>
    )
}
```

<Aside type="caution">
Render `UnistylesStyles` after `children`. `+html.tsx` renders before the page, so calling `useServerUnistyles` in `Root` would only collect the styles of the previous request.

Content inside a `<Suspense>` boundary that suspends on the server (e.g. `React.lazy` or `use`) renders after `UnistylesStyles`. Its styles are applied once the JavaScript loads, and they end up in the styles of the next request, which can come from another visitor. Keep per-request values, such as user data, out of the styles used in that boundary.
</Aside>

If you don't use adaptive themes, add the class of your initial theme to `<html>`, next to the class Expo may set, so that the page uses its CSS variables before the JavaScript loads:

```diff lang="tsx" title="+html.tsx"
- <html {...htmlAttributes}>
+ <html {...htmlAttributes} className={[htmlAttributes?.className, 'light'].filter(Boolean).join(' ')}>
```

`useServerDocumentContext` already includes `react-native-web` styles in `headNodes`, so `includeRNWStyles` is disabled.
In the browser, Unistyles takes over the server styles on its own, so you don't need to call `hydrateServerUnistyles`.

The server doesn't know the browser's color scheme, screen size or breakpoint. Values read during render, e.g. with `useUnistyles`, can differ between the server's HTML and the browser's first render.
Keep styles that depend on them in `StyleSheet` (breakpoints, media queries, adaptive themes), which the server renders as CSS.
