Unistyles 3.0 is fully compatible with Next.js Server Side Rendering (SSR). We're supporting both client and server components.

### Usage

<Tabs>
    <TabItem label="App router">
        To use server-side rendered styles, create the following **client-side** component:

        ```tsx title="Style.tsx" /useServerUnistyles/ /useServerInsertedHTML/ /'use client'/
        'use client'

        import { PropsWithChildren, useRef } from 'react'
        import { useServerUnistyles } from 'react-native-unistyles/server'
        import { useServerInsertedHTML } from 'next/navigation'
        import './unistyles'

        export const Style = ({ children }: PropsWithChildren) => {
            const isServerInserted = useRef(false)
            const unistyles = useServerUnistyles({
                layerRNWStyles: true,
            })

            useServerInsertedHTML(() => {
                if (isServerInserted.current) {
                    return null
                }

                isServerInserted.current = true

                return unistyles
            })

            return <>{children}</>
        }
        ```

        With the component in place, make sure it wraps your body's children:

        ```diff lang="tsx" title="layout.tsx"
        + import '../unistyles'
        + import { Style } from '../Style'

        export default function RootLayout({
        children,
        }: Readonly<{
        children: React.ReactNode;
        }>) {
        return (
            <html lang="en">
            <body>
        +        <Style>
                    {children}
        +        </Style>
            </body>
            </html>
        );
        }
        ```

        <Aside>
        The `unistyles.ts` file is where Unistyles is configured. For more details, refer to the [configuration guide](/v3/start/configuration).
        </Aside>

        With this setup, we will ensure that Unistyles is initialized correctly and injects CSS on the server-side.

        ### Streamed and partial routes

        Transformed React Native components automatically send their generated CSS with the Server Component
        payload. This also applies to streamed Suspense content and client navigation to a partial route, so a
        route-local flush component is not required for `View`, `Text`, and the other transformed hosts.

        `getWebProps` can also generate Unistyles classes for custom DOM elements. Those elements do not pass
        through a transformed host, so place `ServerUnistylesStyles` after that custom DOM subtree:

        ```tsx title="layout.tsx" /ServerUnistylesStyles/
        import { ServerUnistylesStyles } from 'react-native-unistyles/server'

        export default function Layout({ children }: { children: React.ReactNode }) {
            return (
                <>
                    {children}
                    <ServerUnistylesStyles />
                </>
            )
        }
        ```

        The component remains an explicit fallback that flushes styles generated by preceding server-rendered
        siblings. Do not add it after every transformed React Native subtree.

        ### Config (Optional)

        `useServerUnistyles` accepts an optional config object:

        - **`includeRNWStyles`** – a boolean that enables or disables injecting React Native Web default CSS styles. Defaults to `true`.
        - **`layerRNWStyles`** – wraps the React Native Web server snapshot in a lower CSS cascade layer. Enable this for App Router streaming so a snapshot inserted with `useServerInsertedHTML` cannot override host-local RSC styles. Defaults to `false` to preserve the legacy Pages Router cascade.

        `layerRNWStyles` requires browser support for CSS cascade layers. It affects only the server snapshot; React Native Web's client stylesheet remains unlayered. Normal unlayered author rules outrank the layered snapshot, while cascade-layer priority is reversed for `!important`, so audit custom important overrides before enabling it.
    </TabItem>
    <TabItem label="Pages router">
        To use server-side rendered styles, add the following code to your codebase:

        ```diff lang="tsx" title="_document.tsx"
        + import { getServerUnistyles, resetServerUnistyles } from 'react-native-unistyles/server'

            export default class Document extends NextDocument {
        +       static async getInitialProps({ renderPage }: DocumentContext) {
        +           const page = await renderPage()
        +           const styles = getServerUnistyles()

        +           resetServerUnistyles()

        +           return {
        +               ...page,
        +               styles
        +           }
        +       }
        ```

        And add the following use effect to your `_app.tsx`
        ```diff lang="tsx" title="_app.tsx"
        + import { hydrateServerUnistyles } from 'react-native-unistyles/server'

        {/* JSX of your component */}
        + useEffect(() => {
        +     hydrateServerUnistyles()
        + }, [])
        ```

         ### Config (Optional)

        `getServerUnistyles` accepts an optional config object:

        - **`includeRNWStyles`** – a boolean that enables or disables injecting React Native Web default CSS styles. Defaults to `true`.
        - **`layerRNWStyles`** – wraps the React Native Web server snapshot in a lower CSS cascade layer. Defaults to `false`; leave it disabled for the legacy Pages Router cascade unless your integration streams host-local RSC styles.

## Troubleshooting

### Hydration error

If you're not using adaptive themes, you might encounter hydration error on your root html element.
This is because unistyles is adding a className to it based on the current theme.

To fix this simply add `suppressHydrationWarning` to your root html element.

```diff lang="tsx" title="layout.tsx"
- <html lang="en">
+ <html lang="en" suppressHydrationWarning>
```

Or you can directly add the className to your root html element.

```diff lang="tsx" title="layout.tsx"
- <html lang="en">
+ <html lang="en" className="dark">
```
